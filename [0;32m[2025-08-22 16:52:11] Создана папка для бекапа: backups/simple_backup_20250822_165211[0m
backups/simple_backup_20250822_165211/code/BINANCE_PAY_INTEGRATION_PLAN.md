### **Что нужно после получения API ключей:**

#### **1. Настройка API ключей**
```python
# В .env файле добавить:
BINANCE_PAY_API_KEY=your_api_key_here
BINANCE_PAY_SECRET_KEY=your_secret_key_here
```

#### **2. Обновление конфигурации**
```python
# В common/config.py добавить:
binance_pay_api_key: str = os.getenv("BINANCE_PAY_API_KEY", "")
binance_pay_secret_key: str = os.getenv("BINANCE_PAY_SECRET_KEY", "")
```

#### **3. Инициализация сервиса**
```python
# В bot/main.py добавить:
from common.binance_pay_service import binance_pay_service
from common.config import settings

# Инициализация
binance_pay_service.configure(
    settings.binance_pay_api_key,
    settings.binance_pay_secret_key
)
```

## 📊 **ФУНКЦИОНАЛЬНОСТЬ**

### **Поддерживаемые валюты:**
- **USDT** (основная)
- **BTC** 
- **ETH**

### **Суммы платежей:**
- **$1.00** - 1 платная проверка
- **$5.00** - 6 платных проверок (скидка 17%)
- **$10.00** - 15 платных проверок (скидка 33%)

### **Процесс оплаты:**
1. Пользователь выбирает сумму
2. Создается платежный ордер в Binance Pay
3. Генерируется QR-код и ссылка для оплаты
4. Пользователь оплачивает через Binance App
5. Система получает webhook о платеже
6. Баланс автоматически пополняется

## 🔄 **WEBHOOK ОБРАБОТКА**

### **Endpoint:** `/webhook/binance-pay`

### **Верификация подписи:**
```python
def verify_binance_signature(payload: str, signature: str) -> bool:
    """Верификация подписи от Binance Pay"""
    expected_signature = hmac.new(
        settings.binance_pay_secret_key.encode(),
        payload.encode(),
        hashlib.sha512
    ).hexdigest()
    return hmac.compare_digest(signature, expected_signature)
```

### **Обработка событий:**
- `PAYMENT_SUCCESS` - платеж успешен
- `PAYMENT_EXPIRED` - платеж истек
- `PAYMENT_CANCELLED` - платеж отменен

## 🛡️ **БЕЗОПАСНОСТЬ**

### **Меры безопасности:**
1. **Верификация подписи** - все webhook'и проверяются
2. **Таймауты** - платежи истекают через 1 час
3. **Дублирование** - проверка на повторные платежи
4. **Логирование** - все операции записываются
5. **Мониторинг** - алерты при подозрительной активности

### **Обработка ошибок:**
- Неверная подпись → отклонение
- Дублированный платеж → игнорирование
- Истекший платеж → отмена
- Ошибка сети → повторная попытка
